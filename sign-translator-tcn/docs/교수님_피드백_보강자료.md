# 교수님 피드백 보강 자료

확인일: 2026-11-08. 현재 소스, 로컬 샘플 파일, 저장된 YOLO 학습 로그를 확인했다. 현재 자료 수와 과거 학습 실행에 사용한 자료 수를 구분한다. 기존 프로그램과 학습 데이터는 변경하지 않았다.

## 1. 학습 데이터 생성 방법

### 수어 관절 샘플

1. 사용자가 수어 이름을 지정하고 카메라 앞에서 동작한다.
2. MediaPipe로 손과 상체를 추적한다. 손 관절은 손목을 기준으로 이동하고 손 크기로 정규화한다.
3. 양손 각각 21개 점의 x·y·z 126개 값에 어깨 기준 양손 손목 위치 4개 값을 추가해 프레임당 130차원 특징을 만든다. 상체 전체 관절 좌표를 모두 TCN에 넣는 구조는 아니다.
4. 정적 샘플은 한 프레임의 특징 벡터, 동작 샘플은 여러 프레임의 특징 벡터 시퀀스로 저장한다.
5. 일반적인 동작 수집 UI는 약 2초 동안 최소 80ms 간격으로 관측을 수집한다. 추적 누락·처리 속도에 따라 실제 프레임 수가 달라진다. 파일 검증은 6~32프레임을 허용한다.
6. DTW는 이 샘플을 직접 비교하는 기준 자료로 사용한다. TCN은 별도 학습을 실행해 가중치를 학습한다. 샘플 저장과 신경망 학습은 같은 작업이 아니다.

공동 영상 저장 기능을 사용하면 동작 원본 영상도 저장할 수 있다. 현재 TCN의 직접 입력은 RGB 영상이 아니라 관절 특징 시퀀스다. 정적 손 모양 비교는 프레임 간 특징 거리 비교이며, 모든 관절 비교를 DTW라고 부르면 부정확하다.

### YOLO 지문자 사진

학습실에서 카메라 촬영 또는 이미지 가져오기로 사진을 등록한다. 사용자가 자모 종류, train/val 구분, 손 영역 박스를 지정한다. YOLO26 탐지는 원본 전체 사진과 박스·자모 라벨을 이용한다. 사진 분류 모델은 이미지 단위 라벨을 쓰는 별도 방식이다. 탐지와 분류의 데이터 조건·입력 크기를 혼동하지 않는다.

촬영 인원 수, 사람별·세션별·조명별 분포는 이번 파일만으로 신뢰성 있게 확인하지 못했다. 발표 전에 실제 수집 기록으로 보충해야 한다. 사진 수가 많아도 같은 사람·같은 촬영의 유사 프레임이 대부분이면 일반화가 입증되는 것은 아니다.

### TCN: 현재 구현된 학습 설정

| 항목 | 코드 설정 |
|---|---|
| 최소 수집 조건 | 2개 이상 클래스, 모든 클래스에 서로 다른 동작 샘플 5개 이상 |
| 입력 | 프레임당 130차원, 파일 입력 6~32프레임 |
| 특징 정규화 | 학습 입력에서 구한 차원별 평균·표준편차 |
| 모델 | 130→32 채널 투영, causal residual Conv1d 블록 3개 |
| kernel / dilation | kernel 3, dilation 1·2·4 |
| 활성화 / dropout | ReLU / 0.1 |
| 출력 | 유효 프레임 평균 pooling 후 Linear로 클래스 점수 계산 |
| optimizer | Adam |
| 학습률 / weight decay | 0.003 / 0.0001 |
| 손실 함수 | 클래스 가중치를 적용한 CrossEntropyLoss |
| gradient clipping | 최대 norm 1.0 |
| epochs / seed | 100 / 321 |
| 배치 처리 | 증강된 전체 자료를 한 번에 넣는 full batch. YOLO의 batch=8과 다르다. |
| 증강 | 손 슬롯 교환, 한 손 누락 변형, 앞부분 구간, 슬라이딩 구간 생성 |
| 실제 연산 장치 | 현재 코드상 CPU. 모델·텐서를 CUDA로 이동하는 코드가 없다. |
| 학습·검증 분리 | 현재 학습 경로는 전체 증강 자료를 학습에 사용하며 별도 검증·테스트 분리가 없다. |

증강 결과 수를 독립 촬영 수로 세면 안 된다. 평가를 추가할 때는 원본 촬영 또는 사람·세션 단위로 먼저 분리한 다음 학습 쪽에만 증강해야 한다.

현재 활성 TCN 체크포인트 경로 `data/korean-position-tcn.pt`에는 파일이 없다. 따라서 위 표는 구현된 학습 설정이며, 이 설정으로 현재 모델이 학습 완료되어 동작 중이라는 증거는 아니다. 현재 버전의 TCN 정확도·학습 시간·DTW 대비 우위는 확인되지 않았다.

## 4. 브라우저 추론의 뜻

발표 문구:

> 브라우저 추론은 미리 학습한 모델을 웹브라우저 안에서 실행하여, 입력 데이터에 대한 예측 결과를 계산하는 것을 의미합니다. 본 시스템의 YOLO 모델은 ONNX 파일로 내보낸 뒤 ONNX Runtime Web으로 실행합니다. 현재 실행 제공자는 WebAssembly이며, 브라우저 추론이라고 해서 GPU를 사용하는 것은 아닙니다.

| 기능 | 실제 처리 위치 |
|---|---|
| MediaPipe 손·상체 추적 | 브라우저 |
| DTW 관절 시퀀스 비교 | 브라우저 JavaScript |
| YOLO ONNX 추론 | 브라우저 ONNX Runtime Web, executionProviders=[wasm] |
| TCN 학습·추론 | 로컬 Python/PyTorch 서버. 브라우저가 관절 시퀀스를 /api/tcn/predict로 전송 |
| Gemini 문장 보정 | 인식 텍스트를 Google API로 전송 |

DTW는 신경망 모델 추론이 아니라 샘플 거리 비교다. “모든 AI가 브라우저에서 실행된다”, “모든 처리가 외부 전송 없이 수행된다”, “브라우저 추론은 GPU 추론이다”라고 발표하면 부정확하다.

## 5. TCN 설명과 DTW 대비 현재 문제

발표 문구:

> DTW는 현재 동작과 저장한 기준 동작의 시간축을 유연하게 대응시키며 차이를 계산하는 방법입니다. TCN은 여러 프레임의 관절 데이터를 시간축 합성곱으로 처리하여 수어별 동작 패턴을 가중치로 학습하는 신경망입니다. 학습 시 정답과 예측의 오차로 가중치를 조정하고, 추론 시에는 학습한 가중치로 각 수어의 점수를 계산합니다.
>
> 이 프로그램의 TCN은 과거와 현재 입력만 참조하는 인과적 합성곱과 dilation 1·2·4를 사용합니다. 실시간에서는 최근 12~20개 관절 관측값을 슬라이딩 윈도우로 묶고, 최소 150ms 간격으로 추론을 요청합니다. 동일 후보의 반복·점수·유지 시간을 별도 후처리에서 확인해 출력합니다. 슬라이딩 윈도우와 투표는 TCN 자체의 필수 구조가 아니라 이 시스템의 입력·후처리 방식입니다.

관절 관측값은 최소 75ms 간격으로 추출한다. 12~20개 관측값이 곧 카메라 원본 영상 12~20프레임, 또는 150ms 길이의 영상이라는 뜻은 아니다. 이상적인 관측 간격일 때 첫 관측부터 마지막까지 약 0.825~1.425초가 된다. 추적 지연이 있으면 더 길어진다.

현재 확정 로직: 후보 점수 ≥0.85, 1·2위 차이 ≥0.30, 최근 600ms 내 최대 4회 관측에서 같은 유효 후보 ≥3회·75% 이상, 첫 동일 후보부터 ≥300ms, 중복 출력 방지. 점수 0.85는 실제 정확도 85%라는 의미가 아니다.

| 비교 항목 | DTW | 현재 TCN의 고려점 |
|---|---|---|
| 소량 데이터 | 저장 샘플을 바로 비교할 수 있음 | 최소 5개는 실행 조건일 뿐 충분한 데이터라는 뜻이 아님. 현재 클래스 불균형과 부족 샘플이 있음 |
| 속도 차이 | 시간축 정렬을 명시적으로 수행 | DTW와 같은 정렬을 직접 수행하지 않으며 수집·증강으로 속도 변화를 배워야 함 |
| 추적 누락 | 비교 거리 자체가 나빠질 수 있음 | 누락된 좌표가 시간 패턴에도 영향을 줌. 누락 증강만으로 모든 문제를 해결하지 못함 |
| 연속 수어 | 구간 추출·후처리가 필요함 | 단어 중간에 윈도우가 걸릴 수 있음. 현재 단어 사이 연결 동작·비수어를 별도 학습하지 않음 |
| 대기 상태 | 대기 샘플·차단 로직 필요 | softmax는 대기 입력에도 등록 클래스 점수를 줄 수 있음. 높은 점수가 정답 보장은 아님 |
| 확정 지연 | 샘플 비교와 안정화에 시간 필요 | 12프레임 수집·추론·반복 확정에 시간이 필요함. 항상 DTW보다 빠르다고 말할 수 없음 |
| 연산 비용 | 입력 길이와 기준 샘플 수에 따라 증가 | 고정 모델은 샘플 전수 비교를 하지 않지만, 현재는 Python 호출·전처리 지연이 있음. 실제 속도 비교가 필요함 |
| 현재 성능 근거 | 저장 샘플에 대한 시연 | 활성 체크포인트와 독립 평가 부재. DTW보다 정확하다는 결론을 낼 수 없음 |

발표 결론:

> 현재는 소량의 직접 수집 자료로 비교 가능한 DTW를 중심으로 구현했습니다. TCN은 시간 변화 패턴을 학습하는 대안으로 구현했지만, 연속 동작과 비수어 자료 부족, 추적 누락, 독립 평가 부재의 문제가 있어 개선 과제로 제시했습니다. 향후 사람·세션 단위 평가 자료를 분리하고, 같은 자료에서 단어 인식률·대기 상태 오검출률·출력 지연을 비교할 계획입니다.

| nvidia-smi의 CUDA Version 표시 | 13.1: 드라이버 지원 수준. 실제 PyTorch CUDA 빌드 12.4와 구분 |
| 브라우저 YOLO 런타임 | ONNX Runtime Web 1.20.1, WASM |

일반 python 명령은 프로젝트 가상환경과 다르다. 현재 시스템 Python에서는 PyTorch 2.15.0+cpu, CUDA 빌드 없음, CUDA 사용 불가가 조회됐다. 발표에는 확인한 학습 실행의 Python/PyTorch 환경을 써야 하며 시스템 Python 버전을 혼합하면 안 된다.

발표 문구:

> 모델 학습에는 AMD Ryzen 9 7900, NVIDIA RTX 4070 Ti 12GB, 약 32GB RAM을 갖춘 Windows 11 PC를 사용했습니다. 확인한 YOLO 학습은 Python 3.12.9, PyTorch 2.5.1, CUDA 12.4 환경에서 수행됐습니다. TCN은 같은 프로젝트의 Python 환경을 사용하지만 현재 구현은 CPU 연산입니다. YOLO 실시간 추론은 ONNX Runtime Web의 WASM 방식으로 브라우저에서 수행합니다.
