# 한국 수어 TCN 웹사이트 사용 가이드

팔 연결은 몸 관절의 좌우 번호를 유지합니다. 손목 오차로 어깨와 팔꿈치를 함께
이동시키지 않습니다. 손과 어깨는 그대로인데 팔꿈치만 반대편으로 튀면 해당 팔 선과
아바타 팔을 잠시 숨기고 다음 관측을 확인합니다. 자연스럽게 팔을 교차하는 동작은
계속 표시합니다. 손과 어깨로 만드는 기존 인식 입력, 원본 관절 기록은 그대로 사용합니다.
이 보완은 팔 표시 안정화이며 수어 인식률 향상을 확인한 결과는 아닙니다.

대기 동영상 샘플은 일반 수어와 같은 DTW 비교에 함께 넣어 후보를 결정합니다.
DTW가 대기로 판단하면 마지막 한 프레임의 정지 점수와 관계없이 출력을 차단하고,
잠시 유지되면 `수어 대기`로 표시합니다. 다른 수어가 더 잘 맞으면 대기 차단을 해제합니다.
실제 손 이동 중에는 동영상 대기 판정을 적용하지 않아 다음 수어를 시작할 수 있습니다.
`대기 자세 저장` 사진형 자료의 정지 비교도 유지합니다. 원문에 대기 단어를 추가하지 않습니다.

대기 차단이 안 될 때는 대기 자료 수 외에 탈락 이유, 비교 점수/75점 기준, 현재 손 개수,
같은 손 개수 자료 수, 위치 일치 자료 수를 표시합니다. 비교 점수는 정확도가 아닙니다.
한 손 자료가 있어도 불일치하면 양손 대기 자료의 보이는 손으로 추가 비교합니다.
이 부분 비교는 출력 차단 전용이며 가려진 손을 만들어 채우거나 대기를 확정하지 않습니다.

## DTW 정지 수어 비교

정지 수어는 자세를 유지하며 `샘플 저장`을 3회 이상 누릅니다. 2초 수집으로 저장한
경우에도 같은 단어의 3개 이상 녹화가 전체적으로 손 모양·위치를 유지했다면 정지
비교에 사용합니다. 손 이동이 있는 녹화가 섞인 단어는 마지막 자세만으로 확정하지
않고 기존 동작 DTW로 비교합니다. 준비 동작이 섞였다면 자세를 잡은 뒤 다시 수집하세요.

이 처리는 인식 방식을 DTW로 선택했을 때 적용됩니다. TCN을 정지 수어 모델로
재학습하거나 대체하는 변경은 아닙니다. 지문자는 별도 경로, 대기 자세는 출력 차단을
유지합니다. 정지 판별 기준은 실험값이므로 실제 자세의 흔들림과 유사 수어로 평가해야 합니다.

## 수어 대기 자세 등록

카메라를 켜고 평소처럼 손을 모아 배꼽 위나 명치 부근에 둡니다.
`대기 자세 저장`으로 서로 따로 관찰한 자세를 3개 이상 저장하거나,
`2초 대기 자세 수집`을 3회 이상 반복합니다. 손 위치와 각도를 조금씩 달리해
실제 대기 범위를 등록하세요. 양손과 어깨가 보이는 상태가 필요합니다.

`대기 자세 출력 차단`이 켜져 있으면 등록한 손 모양과 어깨 기준 손 위치를 함께
비교합니다. 일치하면 `수어 대기`로 표시하고 TCN·DTW·지문자 출력을 보류합니다.
자세를 벗어나 움직이면 차단을 해제하므로 수어마다 대기 자세로 돌아올 필요는 없습니다.
손이 하나만 보이는 경우 대기 확정에는 그 손 개수의 예제가 3개 이상 필요합니다.
양손 대기 자료가 3개 이상이고 보이는 한 손의 모양·위치가 일치하면 가린 손을
만들어 채우지 않고 `대기 확인 중`으로 단어 출력을 보류합니다. 대기 후보가 잡힌
즉시 비교 점수를 지우며, 목록에서는 일반 정지 수어와 구분해 `대기 전용`으로 표시합니다.

대기 자료는 내부적으로 `__rest__`로 구분되며 단어로 출력하거나 TCN의 수어
정답으로 학습하지 않습니다. DTW 비교에 바로 사용하므로 TCN 재학습은 필요 없습니다.
공동 영상 저장이 켜져 있으면 2초 대기 영상도 SLRT 저장소에 배경 자료로 전달되며,
SLRT 모델 반영은 `SLRT 영상 모델 학습`을 눌러야 합니다. 사진형 저장은 영상이 없습니다.

차단 기준은 실사용 평가 전의 실험값입니다. 손 가림이나 대기 자세와 비슷한 수어는
오판할 수 있으므로 확인이 필요합니다. 목록의 `수어 대기 자세` 자료를 지우거나
차단 체크를 끄면 해제할 수 있습니다. 기존 수어 샘플과 모델은 삭제하지 않습니다.

## 한 번 촬영으로 DTW·TCN과 SLRT 자료 공동 저장

`http://127.0.0.1:5194/?v=shared-motion-1`을 새로고침합니다. 카메라 시작만으로는
녹화하지 않습니다. `동작 원본 영상도 공동 저장 · SLRT 학습용`이 켜진 상태에서
`2초 영상·동작 수집`을 누르면, 오디오 없이 그 동작의 관절과 원본 영상을 함께 수집합니다.

1. `자료 구분`을 학습으로 두고 수어 이름을 입력해 `2초 영상·동작 수집`을 반복합니다.
2. 완료 시 관절 샘플은 기존 DTW·TCN 저장소에, 원본 영상은 원본 촬영 저장소에 저장합니다.
   같은 영상 바이트와 정답·세션·분할은 별도 SLRT MediaPipe 프로젝트의 학습 저장소에도 전달합니다.
3. `TCN 학습`과 새로 추가한 `SLRT 영상 모델 학습`을 각각 누릅니다. 저장만으로 모델이
   재학습되지는 않습니다. SLRT 학습 진행과 학습 미반영 영상 수는 이 화면에서 확인합니다.
4. 영상 모델에는 각 수어와 배경 동작의 학습 영상이 각각 두 개 이상 필요합니다. 휴식·일상
   행동은 아래 `원본 영상 촬영`에서 종류를 선택하고, 저장 동의와 SLRT 자료 전달을 켜 수집합니다.
5. 공동 저장 업로드가 실패하면 `공동 저장 재시도`를 사용합니다. 관절·영상은 저장됐지만
   SLRT 전달만 실패했다면 `자료 전달 재시도`를 누릅니다. 같은 원본을 다시 찍을 필요는 없습니다.

공동 동작 촬영은 학습 자료입니다. 별도 평가에는 `새 촬영 세션`을 만들고 검증/최종 평가를
선택해 원본 촬영을 사용하세요. 검증·시험 영상은 SLRT 저장소에도 같은 분할로 전달하며
학습하지 않습니다. 여러 단어가 있는 연속 영상은 단어 구간 추출 연결 전까지 SLRT에
자동 전달하지 않습니다. 옛날 관절 전용 샘플에서 원본 영상을 복원하지 않습니다.

체크를 끄면 기존 관절 전용 `2초 동작 수집`을 사용할 수 있습니다. 공동 저장 취소나 카메라
중지로 미완료 동작은 저장하지 않습니다. 이미 저장한 원본·SLRT 영상은 관절 샘플 삭제/되돌리기와
별개이며, 관절 목록에서 지운다고 다른 저장소의 영상까지 자동 삭제하지 않습니다.

SLRT 쪽은 같은 원본을 디코딩하고 자체 MediaPipe로 관절을 다시 추출하는 기존 RGB+관절
실험 모델입니다. 브라우저의 확대·보정 관절을 그대로 공식 SLRT 입력으로 바꾸는 것이 아닙니다.
기존 SLRT 자료와 모델은 유지하며 학습 버튼은 해당 프로젝트의 전체 train 자료를 사용합니다.
모델 버전과 학습 보고서는 그 프로젝트에 보존됩니다. 학습은 기존 환경과 잠금·시간 제한을
재사용합니다. 이 연결은 학습 자료 공유이며, TCN/SLRT 실시간 점수 결합은 아직 구현하지 않았습니다.

## 2026-10-19 TCN 초기화

사용자 요청으로 기존 TCN 모델·샘플 백업·학습 스냅샷·과거 평가 자료를
`data/reset-backups/2026-10-19-precision-reset/`로 옮겼습니다. 활성 샘플은 0개이며
새 모델을 학습하기 전까지 TCN은 학습 필요 상태입니다. 원본 영상, YOLO 모델과
사진, 별도 SLRT 프로젝트는 유지했습니다. 이 백업을 새 학습에 자동 복원하지 않습니다.

새 수집은 화면을 새로고침하고 `손 정밀 추적`을 켠 동일 조건에서 진행합니다.
카메라 시작 후 어깨·손 추적을 확인하고 수어 이름을 입력한 다음 `2초 동작 수집`을
여러 번 따로 수행합니다. 최소 두 단어, 각 단어 사용 가능한 동작 다섯 개 이상을
모은 뒤 `TCN 학습`을 누릅니다. 정적 `샘플 저장`과 `원본 영상 촬영`은 이 동작 학습
버튼의 입력을 대신하지 않습니다. 휴식·일상 행동은 별도 원본 촬영·평가 자료로
모으며, 저장만으로 비수어 거절 학습이 완료되는 것은 아닙니다.

## 손 정밀 추적

카메라 화면의 `손 정밀 추적`은 기본으로 켜져 있습니다. 끄면 확대 비교 없이 기본 추적을 사용합니다. 영상 촬영·샘플 수집 중에는 변경할 수 없습니다.

- 기본 손 추적 결과가 있는 작은 손 영역을 정사각형으로 잘라 512px 입력으로 별도 Worker에서 비교합니다. 확대는 원본에 없던 영상 정보를 만들어 주는 초해상도 기능이 아닙니다.
- 250ms당 최대 한 손을 추가 비교하고, 기본 추적에 이미 20ms를 넘게 쓴 프레임은 건너뜁니다. 확대 작업은 비동기로 처리하며 최대 35ms까지만 기다립니다. 늦으면 원래 결과를 사용하고 1초 동안 추가 시도를 쉬며, 이전 작업이 끝나기 전에 다음 작업을 쌓지 않습니다. 기기별 실제 처리 속도 보장은 아닙니다.
- 두 손이 겹친 영역, 프레임 바깥으로 잘린 영역은 확대하지 않습니다. 확대 결과의 손목·크기·모양이 기본 관측과 맞지 않거나 좌우 손 분류가 강하게 충돌하면 사용하지 않습니다. 감지되지 않은 손을 과거 좌표로 채우지 않습니다.
- 손 연결은 두 손의 배정을 동시에 비교하며 이동 방향·위치·모양·좌우 분류를 함께 사용합니다. 220ms 이내 짧은 가림에서는 연결 정보만 기억하고, 없는 손의 관절은 출력하지 않습니다. 완전히 겹친 동일 자세의 두 손을 언제나 구분할 수 있는 것은 아닙니다.
- 보정은 프레임 간격과 실제 변위에 따라 조절합니다. 작은 흔들림에는 강하게, 큰 손·손가락 움직임에는 약하게 적용합니다. 갑작스러운 큰 모양 변화는 다음 관측으로 재확인합니다.
- 인식 시작을 허용하는 움직임 판단에는 확대 전 기본 손 관측을 사용합니다. 확대 모드 전환으로 좌표가 달라졌다는 이유만으로 새 수어 입력을 열지 않습니다.
- 원본 촬영에는 기본 관절을 그대로 저장하며, 확대 비교의 영역·결과·소요 시간·채택 여부는 프레임의 `refinement`에 별도로 기록합니다. 확대 모델은 선택 기능이며 로딩 실패 시 기본 인식은 계속됩니다.

기존 샘플과 TCN 모델은 덮어쓰거나 자동 재학습하지 않았습니다. 추적 연결·좌표 처리 개선과 실제 한국 수어 인식률 향상은 별개이며 실제 촬영으로 비교 평가해야 합니다.

## 휴식 중 TCN 출력 보류

현재 손 움직임이 끝나면, 최근 움직임의 450ms 유지 구간이 남아 있어도 새 TCN 후보를 확정하지 않습니다. 관절 유실 또는 움직임 종료 시 표시 후보와 비교 점수를 해제하고, 이전 요청의 늦은 응답도 버립니다. 연속 동작을 이어 하는 동안 별도의 멈춤은 요구하지 않습니다. 짧거나 정적인 구간의 누락 여부는 실제 수어로 추가 검증해야 합니다.

모델의 100%는 비수어를 포함한 실제 정확도가 아니라 학습한 단어들 사이의 상대 점수입니다. 일상 동작을 수어로 오인하는 문제까지 해결하려면 휴식·일상 행동·전환 동작의 비수어 자료를 수집하고, 비수어를 거절하는 모델 학습과 별도 평가가 필요합니다. 이번 변경은 그 학습을 수행하거나 모든 오인식을 해결한 것은 아닙니다.

## 원본 촬영과 평가

2026-10-19 추가한 수집 기능은 기존 TCN 샘플·모델과 별도입니다. 새 백엔드가 필요한 기능이므로 이번 수정 서버는 `http://127.0.0.1:5194/?v=collection-evaluation-1`에서 실행합니다. 기존 5191 서버와 두 SLRT 프로젝트는 중단하거나 덮어쓰지 않습니다. 직접 실행할 때는 평가용 Python으로 `web_server.py --port 5194`를 실행합니다.

1. 카메라를 켜고 `원본 촬영 · 평가`에서 자료 구분과 촬영 종류를 선택합니다. 한 단어·연속 수어는 정답을 입력하고, 여러 표현은 `안녕하세요, 만나서 반가워요, 나, 이름`처럼 쉼표로 구분합니다.
2. 휴식·일상 행동·전환 동작은 정답 출력이 없는 비수어 자료입니다. 영상·관절 컴퓨터 저장 동의 후 `원본 영상 촬영`을 누르고 `촬영 종료`로 저장합니다. 최대 30초이며 오디오는 기록하지 않습니다. 카메라 중지도 녹화를 종료합니다.
3. 같은 촬영 세션은 같은 자료 구분에만 저장할 수 있습니다. 실제로 날짜·환경을 바꿔 다시 촬영할 때 `새 촬영 세션`을 누르세요. 평가용은 학습용 촬영의 연속 프레임을 쪼개 만드는 대신 별도 촬영합니다.
4. `평가 결과 계산`은 검증·최종 평가 촬영만 사용합니다. 단어 오류율(WER), 누락률, 비수어 분당 오출력을 집계합니다. 기존 학습 자료와 모델은 바뀌지 않습니다. 인식 모드·지문자 방식·학습 버튼은 촬영 중 고정됩니다.
5. 출력 지연이 필요하면 선택 항목에 단어별 구간을 입력합니다. 예: `[{"label":"안녕하세요","start_ms":500,"end_ms":1800}]`. 시간은 녹화 시작 기준 ms이고 정답 순서와 같아야 합니다. 구간 정답이 없으면 지연은 미측정이며, 제공된 시간도 영상 디코딩과 대조한 정확한 프레임 정렬은 아닙니다.
6. 저장 실패 시 페이지를 닫지 말고 `다시 저장`을 누르세요. 미저장 영상은 메모리에 남으며 같은 요청 재전송으로 영상이 중복 저장되지 않습니다. `미저장 영상 버리기`는 서버에 저장된 영상을 삭제하지 않습니다.

새 자료는 `data/recordings/clips/<ID>/rgb.webm`, `metadata.json`에 저장합니다. 원본 손 관절·Pose 실제 관측과 누락 상태, 미디어 시간, 확정 단어·시각, 소스·모델·샘플 식별 해시를 남깁니다. 관절의 프레임 관측 시간과 인코딩된 영상 프레임은 일대일로 검증되지 않았으며 얼굴·입은 아직 추출하지 않습니다. **SLRT 학습에 바로 넣는 완성 데이터가 아니라, 디코딩·동기화·재추출·검토를 위한 원본 보존 단계**입니다. 원본 수집 자료는 기존 `TCN 학습` 버튼에 자동으로 섞이지 않습니다.

지문자 방식에서 `관절 비교 단독`을 선택하면 YOLO 없이 저장된 관절 샘플을 비교할 수 있습니다. 자동·수동 모두 관절 80점 이상을 요구하고, 자동 입력의 움직임·450ms 유지·중복 방지는 그대로입니다. `YOLO + 관절 교차 확인`은 기존 기준을 유지합니다. 두 방식은 평가 기록에서 별도로 집계하며, 어느 쪽이 더 정확한지는 새 평가 촬영으로 확인해야 합니다.

저장·평가 형식과 제한은 `RECORDING-CONTRACT.md`에 기록했습니다. API·녹화·분리·점수 계산 검사는 합성 영상으로 확인한 기능 검증이며 한국 수어 인식률 향상을 의미하지 않습니다.

## 정확도와 연속 처리 검증

### 관절 추적 누락 처리

- 이동 확인은 각 손의 관측 이력을 따로 유지합니다. 한 손이 쉬고 있어도 움직이는 손의 이동량을 평균으로 줄이지 않으며, 반대쪽 손의 등장·누락 때문에 남은 손의 이력을 전부 지우지 않습니다. 사라진 손의 좌표를 현재 입력으로 만들지는 않습니다. 정지 흔들림·검출 순서 변경·손 개수 변경만으로 이동을 인정하지 않는 조건은 유지합니다.
- 손목 이동뿐 아니라 손 크기로 정규화한 손끝의 상대 XY 변화도 확인합니다. 손목이 거의 고정된 손가락 동작을 제외하지 않되, 3프레임 평균·3회 이상 변화·누적 변화폭 조건을 함께 요구합니다. 깊이 추정값의 흔들림은 이동 시작 근거로 사용하지 않습니다.
- TCN 대기 이유에서 `손 이동 확인 대기 · 아직 모델에 보내지 않음`과 `입력 구간의 동작 근거 부족`, 모델 점수 미달을 구분합니다. 0% 이동 대기는 모델이 해당 수어를 0점으로 분류했다는 뜻이 아닙니다.

- 손 추적은 정규화 전 영상 좌표 단계에서 안정화합니다. 손목·손바닥·전체 관절이 매우 가까운 두 검출만 중복으로 제거하며, 가까이 있는 두 손을 무조건 합치지 않습니다. 작은 흔들림은 강하게 완화하고 큰 실제 이동은 빠르게 따라갑니다.
- 손목이 거의 그대로인데 손 모양만 급격히 바뀐 관측은 다음 관측에서 확인합니다. 확인 전 한 프레임은 화면에 이전 손만 유지하고 인식·학습 입력으로는 사용하지 않습니다. 사라진 손을 새 관측처럼 유지하지 않으며 250ms 이상 추적 간격이나 카메라 중지에는 필터를 초기화합니다. 3D 손 좌표에도 같은 보정 강도를 적용합니다.
- 필터는 손 검출의 오류 자체를 해결하지 않으며 빠른 실제 손 모양 변화가 한 관측 늦어질 수 있습니다. 기존 모델의 실카메라 정확도 개선은 별도 검증이 필요합니다. YOLO는 여전히 원본 카메라 영상을 분류합니다.

- 양팔을 독립적으로 표시합니다. 한쪽 팔꿈치가 누락되어도 반대쪽 팔은 지우지 않으며, 누락된 팔꿈치 위치를 임의 생성하지 않습니다. Pose 손목만 놓쳤고 같은 쪽 손 추적이 유효하면 실제 손 모델의 손목을 연결합니다.
- 어깨는 처음 연결할 때 기존 0.55 기준을 유지합니다. 연결 후에는 220ms 이내의 기존 기준과 비교해 중심 변화가 어깨 폭의 15% 미만, 폭 변화가 20% 미만인 경우에만 점수 0.4 이상의 실제 관측을 이어받습니다. 약한 관측만으로 새 추적을 시작하지 않습니다.
- 실제 어깨 누락 시 이전 기준은 최대 220ms 복귀 대기로 구분하여 보존하지만, 그 기준으로 새 인식 벡터나 학습 샘플을 만들지 않습니다. 기존 TCN의 짧은 누락 보존 경로로 복귀를 기다립니다. 카메라 중지·영상 정체에는 보존 기준도 초기화합니다.
- 현재 TCN 입력은 손 관절 126개 값과 어깨 기준 손목 위치 4개 값입니다. 팔꿈치 선 누락 자체가 TCN 입력 누락을 뜻하지는 않으며, 어깨 기준 또는 손 추적의 누락은 실제 입력에 영향을 줍니다. 팔꿈치를 모델 입력에 추가하는 변경은 별도 스키마와 재수집·재학습이 필요합니다.

- `evaluate_tcn.py`는 기존 녹화 281개를 단어별로 학습 221개·평가 60개로 먼저 나누고, 학습 쪽에만 기존 증강을 적용합니다. 정규화 통계도 학습 쪽에서만 계산합니다. 운영 모델과 샘플은 덮어쓰지 않습니다.
- 2026-10-17 평가: 미사용 단독 녹화의 전체 구간 분류는 60/60, 이동 창 점수에 실제 출력 확인 조건을 적용한 결과는 58/60, 출력 없음 2개였습니다. 보고서는 `data/tcn-holdout-report.json`, `data/tcn-holdout-stream-report.json`입니다. 같은 촬영 환경의 녹화 분할이므로 새로운 사용자·촬영 세션·연속 문장 정확도가 아닙니다. 평가용 학습 결과는 운영 모델에 설치하지 않았습니다.
- `evaluate_stream.py`와 `evaluate_stream.js`는 현재 모델의 기존 학습 녹화와 인공 연결 구간을 재생하여 회귀를 확인합니다. 이번 확인 조건 변경 전후 모두 기존 녹화 276/281개에서 기대 단어만 출력했고, 인공 두 단어 연결 47/56개에서 기대 순서만 출력했습니다. 이는 학습 데이터 재생 및 합성 연결 시험으로 실사용 정확도가 아닙니다.
- 실제 정확도 개선 검증에는 정답 순서가 있는 자연스러운 연속 수어와 휴식·키보드·얼굴 만지기 등 비수어 녹화가 필요합니다. 이 구간들을 별도 촬영 세션 단위로 학습과 평가에 나눠야 합니다. 기존 단어 샘플을 연결하거나 정지 프레임을 반복하는 것만으로는 대체할 수 없습니다.

## 지문자로 고유명사 입력

### YOLO와 DTW 관절 교차 확인

- 후보 비교와 입력 확정을 분리합니다. 손이 추적되면 움직임 중에도 최소 150ms 간격으로 비교하며 입력은 기존 손목 안정 조건을 통과한 관측에서만 허용합니다. 관절 재확인 중·손 누락에는 입력을 보류합니다. 안정된 지문자 후보는 상단 수어 후보 영역에도 표시하고, 일치하더라도 새 움직임 대기·시간 만료·중복 방지 등 실제 보류 이유를 표시합니다. 정지한 채 카메라를 시작해도 후보는 볼 수 있지만 자동 문장 입력은 새 움직임 조건이 필요합니다.

- 자동·수동 지문자 모두 YOLO와 관절 비교가 같은 자모를 가리킬 때만 입력합니다. 자동은 YOLO 90% 이상·관절 비교 80점 이상, 수동은 각각 80%·80점 이상입니다. 두 점수는 별도 기준이며 평균하거나 정확도로 해석하지 않습니다. 기존 450ms/300ms 유지·움직임·중복 방지 조건도 적용합니다.
- 관절 비교는 저장된 정지 샘플과 동작 녹화당 마지막 자세 1개를 정지 비교하고, 최근 최대 20프레임을 지문자 동작 샘플과 DTW 비교합니다. 동작만 저장한 자모도 끝 자세를 활용하지만 한 녹화를 여러 독립 샘플로 부풀리지 않습니다. 정지 비교와 DTW가 각각 기준을 넘으면서 다른 라벨이면 보류합니다. 일반 수어의 끝 자세도 정지 비교 경쟁 후보로 포함합니다.
- 지문자는 손 모양 126개 값으로 비교하고 저장된 130/136개 값에서는 손 부분만 사용하므로 어깨 누락만으로 교차 확인을 멈추지는 않습니다. 일반 TCN/DTW 수어에는 기존 어깨 기준을 유지합니다. 같은 자모의 관절 샘플이 최소 3개 필요하며 샘플 부족·추적 누락·불일치에는 YOLO 단독으로 우회하지 않습니다.
- 화면에 두 결과와 보류 이유를 표시합니다. 일반 TCN/DTW 단어 출력 경로로 자모가 교차 확인 없이 들어가는 것도 막습니다. YOLO가 지원하지 않는 자모는 관절 샘플만 있어도 입력되지 않습니다. 현재 제공 YOLO는 ㄱ·ㄴ·기타만 지원합니다.
- 교차 확인의 실카메라 인식률·입력 지연 개선은 아직 검증하지 않았으며, 한 모델이 놓치면 누락이 늘 수 있습니다. 관절 비교는 YOLO 요청 시에만 실행하고 500ms보다 오래된 비교는 확정하지 않습니다. 기존 사진·관절 샘플과 모델은 다시 학습하거나 덮어쓰지 않았습니다.

### 버튼 없이 수어와 지문자 함께 입력하기

1. YOLO의 ONNX와 같은 모델의 라벨 파일을 연결합니다. `자동 지문자 · 실험`은 기본으로 켜져 있습니다. `지문자 입력` 버튼을 누를 필요가 없습니다.
2. 카메라를 켜고 TCN 또는 DTW 수어를 수행하다가 지문자를 보여 줍니다. 자동 모드에서는 TCN 좌표 수집·추론을 유지하고 YOLO도 함께 확인합니다. YOLO 추론은 동시에 하나, 최소 150ms 간격이며 손목이 400ms 안정된 뒤 수행합니다. 지문자는 손만 추적되어도 실행하며 어깨 추적 누락으로 중단하지 않습니다. TCN 좌표에는 계속 어깨 기준이 필요합니다. 손이나 새 영상이 없으면 지문자 결과 영역에 대기 이유를 표시합니다.
3. 손 영상 좌표의 실제 변화가 먼저 관측되고, 같은 자모 후보가 90% 이상으로 450ms 유지되면 문장에 추가합니다. 한 번 입력하면 새 손 움직임이 있어야 다음 글자를 받습니다. 정지한 채 예측 글자만 달라지거나 조합 시간이 끝나도 재입력하지 않습니다. 움직임 허가는 2.5초 뒤 만료됩니다. 이어지는 자모는 같은 보호된 문자열에 조합됩니다. 수동 모드의 80%·300ms와 별도 기준이며 실제 정확도는 아닙니다.
4. 최근 500ms 안에 확실한 지문자 후보가 있었으면 TCN/DTW의 겹치는 단어 확정을 보류합니다. 보류한 TCN 단어는 다음 관측에서 다시 확정할 수 있게 재무장하며 분석 프레임은 지우지 않습니다. 완벽한 동작·지문자 구간 분리가 아닌 휴리스틱입니다.
5. 최근 자모 후보가 1.4초 동안 없거나 다음 일반 수어가 확정되면 현재 문자열을 닫습니다. 이미 문장에 보이므로 완료 버튼을 기다릴 필요는 없습니다. 이 시간 안의 서로 다른 고유명사는 한 문자열로 묶일 수 있습니다.
6. 같은 글자는 유지 중 중복 입력하지 않습니다. 높은 점수의 `기타`가 400ms 이상 관측된 뒤 같은 글자를 다시 보여주면 재입력할 수 있습니다. 짧은 추적 누락이나 낮은 점수만으로는 재무장하지 않습니다.
7. 오입력이 많으면 자동 지문자를 끄고 기존 수동 버튼을 사용할 수 있습니다. 문장 지우기는 자동 조합과 후보도 초기화합니다. 샘플 수집 중 자동 지문자는 실행하지 않습니다.

정지 오입력 방지: 손 영상 XY 좌표를 3프레임 평균하여 12프레임 안에서 지속적인 이동을 확인합니다. 깊이 추정·어깨 기준의 흔들림이나 손 개수 변경만으로 입력을 열지 않습니다. 처음 입력을 열 때보다 이어지는 동작에는 낮은 움직임 기준을 적용합니다. 220ms 이내 손 추적 누락에서는 출력을 멈추되 복귀 시 진행 상태를 잠시 보존합니다. TCN은 마지막 유효 이동 후 450ms를 지나면 결과 확정을 중단하지만 최근 20프레임은 계속 모아 재시작 지연을 줄입니다. 1초 이상 정지하면 이전 단어 중복 방지를 해제하되 새 움직임이 있어야 다시 추론합니다. 지문자 손목 정지 기준은 프레임 간 영상 좌표 0.015 이하입니다. 보수적인 조건이라 작거나 느린 수어를 놓칠 수 있으며, 일상 동작과 수어 의도를 구분하는 학습을 대체하지 않습니다.

현재 모델은 ㄱ·ㄴ·기타만 분류합니다. 모음과 나머지 자모는 아직 학습하지 않아 이름 전체를 입력할 수 없습니다. 일반 수어 중 나타나는 ㄱ·ㄴ과 지문자의 의도를 영상 한 장만으로 구분할 수 없으며, 일반 수어 자세·전환 동작을 기타로 더 수집해야 합니다. 통합 경로와 모의 연속 입력은 테스트했지만 실제 연속 카메라 인식률은 검증하지 않았습니다.

### ㄱ / ㄴ / 기타 추가 시험 모델

- 새 모델은 `data/yolo-gn-smoke/fingerspell.onnx`, 라벨은 같은 폴더의 `labels.json`입니다. 두 파일을 함께 교체해야 합니다. 기존 `yolo-g-smoke` 모델은 그대로 보존합니다.
- ㄴ 사진 50장 중 흐림·잘림이 큰 13장(10, 16, 18, 27, 29, 32, 33, 39, 40, 41, 42, 45, 47번)은 학습·검증에서 제외했습니다. 원본은 삭제하지 않았습니다. 나머지는 학습 29장·검증 8장으로 묶음 분리했습니다.
- 학습 시점 전체 폴더에는 ㄱ 학습 61장·검증 31장, ㄴ 학습 29장·검증 8장, 기타 학습 30장·검증 5장이 있었습니다. 기존 파일은 임의로 제거하거나 재배치하지 않았습니다.
- Python/PIL 검증은 ㄱ 25/31, ㄴ 8/8, 기타 5/5였습니다. 실제 Chrome의 동일 검증 사진 재생은 ㄱ 24/31, ㄴ 8/8, 기타 5/5(합계 37/44)였습니다. ㄱ의 경우 입력 기준 점수 80%까지 통과한 것은 21/31장입니다.
- 이는 소규모 검증 묶음 결과이며 실시간·새 촬영·다른 사용자 성능이 아닙니다. ㄱ과 ㄴ의 촬영 시점·복장·배경 차이가 모델 판단에 영향을 주었을 가능성이 있어 동일 조건으로 여러 자모를 교차 촬영하는 후속 확인이 필요합니다.

### 기존 ㄱ / 기타 모델 사용

- `data/yolo-g-smoke/fingerspell-g.onnx`와 `data/yolo-g-smoke/labels.json`을 YOLO 모델·라벨 입력에서 선택한 뒤 `모델 연결`을 누릅니다.
- 카메라를 켜고 `지문자 입력`을 누릅니다. `ㄱ`이 안정되면 입력되고, `기타`는 글자로 추가되지 않습니다. 다시 같은 ㄱ을 넣으려면 `같은 글자 다시`를 누릅니다.
- 학습 사진은 ㄱ 46장·기타 30장, 검증 사진은 ㄱ 10장·기타 5장입니다. 비슷한 연속 사진은 묶어 분리했으나 독립된 사용자·촬영 환경 검증은 아닙니다.
- Python/PIL 전처리 검증은 14/15, 실제 Chrome Canvas 전처리 사진 재생은 15/15였습니다. 리사이징 구현 차이에 민감할 수 있으며, 이 수치는 실시간 카메라 정확도나 일반화 성능을 의미하지 않습니다. 같은 검증 묶음으로 최적 에포크도 선택했으므로 별도의 새 촬영이 필요합니다.
- 원본 사진, TCN 모델은 보존합니다. 학습 산출물과 의존성은 Git 제외 대상인 `data/`에 있습니다.
- 재현 스크립트는 `train_fingerspell.py`입니다. 공식 YOLO11n-cls에서 시작하고, 자르기·좌우 반전 없이 전체 영상을 224×224 letterbox한 RGB 0~1로 학습합니다. 기존 `data/yolo-g-smoke`가 있으면 덮어쓰지 않고 중단합니다.
- 사진과 추론은 로컬에서만 처리합니다. 첫 실행의 ONNX Runtime 다운로드에는 인터넷 연결이 필요합니다.

### 수동 지문자 입력

1. YOLO11-cls로 학습한 지문자 ONNX 모델과 라벨 파일을 연결합니다. 라벨은 `ㄱ`, `ㅏ` 같은 호환 자모 한 글자입니다. 일반 사물 모델이나 기존 DTW 좌표 JSON은 사용할 수 없습니다.
2. DTW 또는 TCN으로 일반 수어를 수행하다가 `지문자 입력`을 누릅니다. 이름·브랜드·지명 모두 같은 방식이며 특정 문장 트리거는 필요하지 않습니다.
3. 이 모드에서는 DTW·TCN 단어 확정과 샘플 수집을 멈춥니다. 손목이 400ms 안정된 뒤 YOLO를 최소 150ms 간격으로 실행하고, 80% 이상 같은 자모 후보가 300ms 유지되면 입력합니다. 점수는 실제 정확도가 아닙니다.
4. 입력 중인 한글은 별도 칸에 표시됩니다. `⌫`는 마지막 자모를 삭제하고, `같은 글자 다시`는 같은 자모를 연속 입력하도록 재무장합니다. 추적 누락만으로 같은 글자를 자동 반복하지 않습니다.
5. `입력 완료`를 누르면 조합된 문자열을 문장에 한 단어로 넣고 원래 인식 방식으로 돌아갑니다. `취소`는 미완성 입력을 버립니다. 입력한 고유명사는 규칙 기반 말투 변환에서 바꾸지 않습니다.

지문자 모델은 별도 준비해야 하며, 실제 지문자 카메라 정확도는 검증하지 않았습니다. 현재 전처리는 전체 영상을 224 등 모델 입력 크기로 letterbox한 RGB 0~1 입력입니다. 학습·내보내기의 전처리와 반드시 맞춰야 합니다. 손 자르기 학습 모델을 그대로 연결하면 맞지 않습니다. 움직임을 구분해야 하는 지문자는 정지 이미지 분류만으로 충분하지 않을 수 있습니다.

YOLO는 MediaPipe와 GPU를 경쟁하지 않도록 WASM으로 실행합니다. 실제 처리 속도는 장비와 모델 크기로 확인해야 합니다. 한글 조합은 포함된 MIT 라이선스의 hangul-js 0.2.6을 사용합니다.
현재 포함된 ONNX Runtime이 입력 메타데이터를 제공하지 않으면 224×224 입력을 사용하므로 우선 `imgsz=224`로 내보낸 모델을 연결하세요.

## TCN 학습 진단 변경

- 기존 모델과 샘플을 자동으로 재학습하거나 덮어쓰지 않습니다.
- 모델 연결 상태에 학습된 원본 동작 수와 최근 구간 학습 여부를 표시합니다.
- 실시간 후보 아래에는 점수 미달, 후보 간 차이 미달, 유지 시간, 움직임 미달, 중복 출력 차단을 구분해 표시합니다. 학습 문제와 출력 조건 문제를 구분하기 위한 진단입니다.
- 다음 `TCN 학습`부터 전체·앞부분 증강에 더해 실제 추론과 같은 최근 12~20프레임 구간도 학습합니다. 기존 `.pt`는 `.pt.bak`으로 보존합니다.
- 학습 중 사용·제외 동작 수, 실패 시 서버 오류를 표시합니다. 정지 샘플은 TCN 학습 대상이 아닙니다. 126차원 샘플, 단어별 5개 미만, 중복 동작도 실패 원인이 될 수 있습니다.
- 구간 증강은 연속 수어 학습을 대체하지 않습니다. 단어 연결과 비수어 데이터는 여전히 추가 수집·별도 평가가 필요하며 개선된 정확도를 주장하지 않습니다.

- TCN 사이트는 http://127.0.0.1:5191/?v=tcn-position-1 입니다.
- `run_tcn.bat` 또는 `..\slrt-evaluation\.venv\Scripts\python.exe web_server.py --port 5191`로 실행합니다.

- 초기 MediaPipe 모델과 3D 라이브러리 다운로드에는 인터넷 연결이 필요합니다.
- 별도 지시 전까지 Git 커밋과 푸시는 하지 않습니다.

## 먼저 사용하기

1. 다른 사이트나 탭의 카메라를 중지하고 새 TCN 주소를 엽니다.
2. 인식 방식을 `TCN 연속 · 실험`으로 선택하고 모델 연결 상태를 확인합니다.
3. `카메라 시작`을 누르고 양어깨와 손이 보이도록 합니다.
4. `안녕하세요` 다음에 `만나서 반가워요`를 이어서 수행합니다. 첫 결과를 기다리는 조작은 필요하지 않습니다.
5. 후보와 비교 점수는 오른쪽에 표시되고 확정된 단어는 인식 원문에 순서대로 추가됩니다.
6. 다시 시험할 때 문장 지우기를 누릅니다. 문장 지우기와 카메라 중지는 TCN 버퍼도 초기화합니다.

연속 처리 경로가 구현된 것이며 실제 두 단어 연결 정확도를 보장하지 않습니다.
현재 모델은 개별 단어 샘플과 부분 동작으로 학습했습니다. 실제 연결 동작과 비수어 구간은 아직 학습하지 않았습니다.

## 잘되는 DTW 페이지에서 가져온 부분

- Heavy Pose GPU 추적과 0.35 신뢰도 설정, 손 추적 설정을 유지합니다.
- 손모양 126개와 어깨 기준 손목 위치 4개를 합친 130개 좌표를 두 모드에서 동일하게 사용합니다.
- 같은 아바타 연결과 2초 동작 수집, 컴퓨터 자동 저장, 64MB 백업 불러오기를 사용합니다.
- DTW 비교 모드는 한 손이 보이면 누락 시간 제한 없이 비교합니다. 부분 동작 유사도 40% 이상, 후보 간 차이와 실제 움직임 조건을 만족하면 종료 후 확정합니다.
- 동작 샘플이 단어별 3개 이상이면 해당 단어를 마지막 정지 손모양만으로 확정하지 않습니다.
- TCN도 한 손이 보이는 동안 분석을 계속합니다. 두 손 또는 기준 좌표가 모두 사라지면 220ms 보호 후 버퍼를 초기화합니다.
- 누락된 손 좌표를 이전 값으로 만들어 넣지 않습니다.
- 현재 인식은 어깨 기준 좌표가 필요합니다. 어깨 추적 실패 시 손이 보여도 입력이 만들어지지 않을 수 있습니다.

## TCN 확정 조건

- 최소 75ms 간격으로 관측 프레임을 모으며 최소 12프레임부터 최근 최대 20프레임을 분석합니다.
- 요청 간격은 최소 150ms이며 추론 요청은 동시에 하나만 실행합니다.
- TCN 모델 점수 85% 이상, 두 번째 후보와 점수 차이 30%포인트 이상인 관측을 최근 600ms·최대 4회에서 집계합니다. 같은 후보를 3회 이상, 관측의 75% 이상에서 확인하고 첫 지지 관측부터 300ms가 지나면 추가합니다. 한 번의 낮은 점수로 모두 초기화하지 않으며, 정상적으로 150ms마다 판단하면 확인 시간은 기존과 같은 300ms입니다. 멈춤 없이 다음 단어로 넘어갈 수 있습니다.
- DTW 유사도 40%를 TCN 모델 점수에 그대로 적용하지 않습니다. 둘 다 실제 정확도로 보정된 확률이 아닙니다.
- 동작 중에도 후보를 갱신하므로 DTW 종료 판정을 기다리지 않습니다. 같은 단어의 중복 출력은 막고 다른 단어로 바뀌면 다음 단어를 추가할 수 있습니다.
- 움직임이 거의 없는 입력은 추론하지 않습니다. 손 개수가 바뀌는 것만으로 움직임으로 판단하지 않습니다.
- 12프레임 수집과 후보 유지에 시간이 필요하므로 지연 0초를 보장하지 않습니다.
- 같은 단어를 반복하려면 버퍼 초기화가 필요할 수 있습니다.
- 큰 일상 움직임은 여전히 오인식될 수 있습니다. 통역용 완성 모델이 아닙니다.

## 샘플과 재학습

1. 단어마다 `2초 동작 수집`으로 별개의 동작을 최소 5개씩 모읍니다.
2. 최소 2개 단어의 130개 좌표 동작 샘플이 있어야 TCN 학습이 가능합니다.
3. 수집이 끝나면 `TCN 학습`을 누릅니다. 카메라가 중지됩니다.
4. 완료 후 TCN 모드를 선택하고 새 촬영으로 확인합니다.

130차원과 과거 입모양 포함 136차원 동작은 손·위치 130개만 읽어 학습합니다.
126차원 손 전용 샘플은 손목의 어깨 상대 위치가 없으므로 이번 모델 학습에서 제외합니다.
제외된 원본 샘플은 삭제하지 않으며 모델 상태에 재수집이 필요한 단어를 표시합니다.
같은 단어의 130차원 샘플을 새로 수집하거나 잘되는 사이트의 백업을 불러온 뒤 재학습합니다.
정지 vector만 있는 샘플은 TCN 학습에 사용하지 않습니다.
TCN 사이트의 샘플과 모델은 원래 DTW 사이트와 자동 공유하지 않습니다.

새 학습은 전체 동작, 앞부분 60/75/90% 동작, 손 감지 순서 교환, 한 손만 남은 입력 변형을 포함합니다.
한 손 변형은 손모양과 손목 위치를 함께 옮기며 원본 샘플 파일은 수정하지 않습니다.
이 변형은 추적 누락 대응용이며 실제 다양한 사람이나 연결 동작을 수집한 대체물이 아닙니다.

### YOLO 전용 학습실

#### 손 박스 직접 라벨링

인식 화면의 **관절·손 박스 표시**를 켜면 탐지 모델의 손 박스와 글자/점수가 노란색으로 표시됩니다. 모델 입력의 여백을 제거한 실제 영상 위치이며, 학습 사진의 박스를 그대로 붙이는 기능이 아닙니다. YOLO 지문자 비교가 동작하는 동안 표시하고, 관절 단독 모드·손 추적 누락·오래된 결과에서는 숨깁니다. 기존 사진 분류 모델에는 위치 출력이 없어 박스가 나오지 않습니다. 표시 점수는 정확도가 아니며 박스 표시만으로 글자가 문장에 확정되지는 않습니다.

1. 사진을 촬영/추가하거나 기존 사진의 **박스 편집**을 엽니다.
2. **박스 글자**를 입력하고 손 전체(손가락 끝 포함)를 드래그해서 둘러쌉니다. 사진을 반전하지 않습니다.
3. 박스 목록에서 선택하면 이름과 X/Y/폭/높이(사진 대비 %)를 수정할 수 있습니다. 다른 글자의 박스는 **새 박스**를 누른 뒤 추가합니다. 삭제·되돌리기도 가능합니다.
4. **저장 후 다음**으로 계속 작업합니다. 지문자 대상이 없는 사진은 **대상 없음 (배경)**을 선택해 저장합니다. 아직 손 박스를 그리지 않은 사진과 배경 사진은 다르게 취급됩니다.
5. **손 박스 탐지 · YOLO11n**을 선택해 학습합니다. 박스 작업을 저장한 사진만 사용하며, 글자별 학습용 5장·검증용 2장 이상이 필요합니다. 이미지에 있는 대상 손은 모두 표시하세요. 배경 사진만으로는 학습할 수 없습니다.
6. 완료된 기록에서 ONNX와 **같은 기록의 labels.json**을 저장해 수어 인식 화면의 YOLO 모델에 연결합니다. 탐지용 라벨에는 모델 종류·320 입력 크기가 들어 있어 기존 분류용 라벨과 섞으면 안 됩니다. 기존 분류 모델도 계속 지원합니다.

탐지 학습은 `data/yolo11n.pt` 공식 기본 모델을 사용하고, 정규화한 중심좌표·폭·높이 형식으로 학습 복사본을 만듭니다. 형식은 [Ultralytics 탐지 데이터 규격](https://docs.ultralytics.com/datasets/detect/)을 따릅니다. 사진 원본과 기존 분류 이름/모델은 유지됩니다. 기존 사진도 새로 찍지 않고 박스를 붙일 수 있습니다.

탐지 기록에는 ONNX 검증의 mAP50과 mAP50–95를 표시합니다. 분류 정답률과 다른 지표이며 실제 카메라 정확도를 보장하지 않습니다. 현재 실시간 입력은 손을 찾지 못하거나 서로 다른 글자의 손이 동시에 감지되면 보류하고, 기존 관절 교차 확인도 유지합니다. 이 기능만으로 TCN/SLRT 동작 모델이 재학습되지는 않습니다.

- 별도 주소: `http://127.0.0.1:5196/`. 인식 페이지의 YOLO 영역에도 열기 링크가 있습니다.
- 서버가 꺼졌다면 이 폴더에서 `./scripts/start-yolo-studio.ps1`을 실행합니다. 기존 5194 인식 서버와 독립적입니다.
- 이름(예: ㄱ, ㄴ, 대기, 기타)을 입력하고 카메라 사진 촬영 또는 사진 추가를 사용합니다. 원본 화면 전체를 저장하며 손만 자르거나 좌우 반전하지 않습니다.
- 최소 두 종류, 종류별 학습용 5장·검증용 2장이 필요합니다. 이는 실행 최소 조건이지 정확도 보장 조건이 아닙니다. 자세·거리·조명·배경을 바꾼 충분한 자료를 모으세요.
- 검증용은 학습용 촬영과 별도로 촬영해 지정합니다. 같은 사진의 중복은 막지만, 비슷한 연속 프레임까지 자동 판별하지는 않습니다.
- 학습 시작은 기존 YOLO11n-cls 기본 가중치에서 새 모델을 만듭니다. 기존 사용자 모델을 덮어쓰거나 자동 이어 학습하지 않습니다. GPU가 있으면 GPU, 없으면 CPU를 사용합니다. 다른 TCN/SLRT 학습과 동시에 실행하지 않는 편이 좋습니다.
- 학습 시점 사진 복사본으로 학습하므로 이후 사진 추가·삭제는 현재 작업에 영향을 주지 않습니다. 학습 중단은 이번 작업만 멈추며 사진과 이전 완료 모델은 남습니다.
- 기존 전체 화면 입력과 맞춰 회색 여백을 넣은 224×224 RGB/255 입력을 사용합니다. 좌우 반전 증강은 하지 않습니다.
- 학습 완료 후 ONNX 모델과 라벨을 저장하여 기존 인식 페이지의 모델/라벨 선택란에 각각 연결합니다. 자동 적용되지 않습니다.
- 표시된 검증 결과는 내보낸 ONNX의 해당 검증 사진 결과입니다. 실시간 연속 수어 정확도나 독립적인 최종 시험 결과가 아닙니다. 지문자·정지 사진 분류이며 동작 순서를 학습하지 않습니다.
- 새 자료와 모델: `data/yolo-studio/`. 기존 `data/fingerspell-images`, TCN/DTW/SLRT 자료는 자동 복사·변경·삭제하지 않습니다. 브라우저 창을 닫아도 실행 중인 학습 서버가 작업을 계속합니다.

- 기존 컴퓨터 샘플 파일이 있으면 우선 읽고 파일이 없을 때만 브라우저 샘플을 이전합니다.

# 자동 지문자가 원문에 들어가지 않을 때

문장이 표시된 상태에서 Enter 또는 '문장 읽기 · Enter'를 누르면 브라우저의 한국어 TTS로 다듬은 문장을 읽습니다. 다듬은 문장이 없으면 원문을 사용합니다. 실제 음성 재생이 시작되면 원문·다듬은 문장·지문자 조합을 비웁니다. 재생 시작 전 오류나 미지원 상태에서는 문장을 유지하며, 기다리는 사이 새 문장이 입력되면 그 문장을 지우지 않습니다. 입력칸·선택 목록·설정 창에서의 Enter와 한글 조합 중 Enter는 단축키로 처리하지 않습니다. 재생 중에는 중복 음성을 추가하지 않습니다. 카메라는 계속 사용할 수 있습니다. 한국어 음성의 제공 여부와 발음은 브라우저·운영체제의 TTS 환경에 따라 달라집니다.

지문자 방식에서 'YOLO 단독 · 관절 비교 안 함'을 선택할 수 있습니다. ONNX 모델과 라벨은 필요하지만 관절 샘플은 필요하지 않습니다. 손 관절의 검출·유사도·움직임·관절 기반 대기 자세는 이 방식의 지문자 입력 조건에 포함하지 않습니다. YOLO 60% 이상인 같은 글자가 자동 입력에서는 450ms, 수동 입력에서는 300ms 유지되면 입력하며, 계속 같은 글자를 유지하면 중복 입력하지 않습니다. 추론이 오래 걸리거나 카메라가 중단되면 결과를 버립니다. 관절 검증을 사용하지 않으므로 YOLO 오분류가 문장에 들어갈 가능성이 커집니다. 화면의 관절·팔 표시 및 일반 수어 비교는 별도로 계속 동작합니다. 기존 'YOLO + 관절 교차 확인'과 '관절 비교 단독'도 그대로 선택할 수 있습니다.

한 손에 관절이 중복 표시되면 손목과 손바닥 기준점이 겹치는 검출을 하나로 정리합니다. 손가락 끝 추정이 서로 달라도 손바닥이 같은 경우를 포함합니다. 팔 선을 그릴 때는 손 관절이 해당 팔의 몸 손목과 가까운지 확인하며, 반대 팔에 더 가깝거나 너무 멀면 몸 추적 손목을 사용합니다. 몸 손목도 보이지 않고 연결 근거가 부족하면 해당 팔 선을 그리지 않습니다. 화면에 나타나는 모든 겹침을 해결하는 것은 아니므로, 실제 두 손을 교차하는 동작과 추적 누락은 함께 확인해야 합니다.

지문자의 '관절 자세·동작 불일치'는 현재 손 모양과 최근 시퀀스의 후보가 다르다는 뜻입니다. 손목이 안정되고 최근 네 관절 프레임의 손 모양도 현재와 충분히 가까우면 현재 정지 자세의 지문자 후보를 우선합니다. 이때도 YOLO와 글자가 같고 각각 점수 기준을 넘어야 입력되며, 손가락 모양이 바뀌는 중에는 충돌 보류를 유지합니다. 충돌 문구에는 자세 후보와 동작 후보를 각각 표시합니다. YOLO가 60% 아래로 내려가면 관절이 일치해도 입력은 보류됩니다.

YOLO와 관절이 같은 글자인데 '일치 · 새 손 움직임 대기'로 나오면 점수가 아니라 입력 시작 움직임 조건에 걸린 것입니다. 지문자에는 작은 위치 이동·손가락 모양 변화용 움직임 감지를 별도로 적용하며, 수어 단어의 DTW·TCN 움직임 기준은 유지합니다. 손 안정·교차 확인·유지 시간·중복 방지는 계속 적용됩니다. 처음부터 같은 자세로 가만히 있으면 자동 입력하지 않습니다. 전용 화면에서는 카메라 아래 '지문자 인식 상태'에서 YOLO·관절 점수와 보류 이유를 볼 수 있습니다.

카메라·문장 전용 화면은 http://127.0.0.1:5194/frontend/live.html 입니다. 기본 화면에는 카메라와 문장 조합만 표시하며 '모델·인식 설정'에서 YOLO 모델, 인식 방식, Gemini API 설정을 연결합니다. 학습·샘플 관리는 상단 '학습·관리'로 이동하세요. 모델은 페이지마다 별도로 연결해야 합니다. 실시간 3D 아바타 화면과 렌더링은 제거했습니다. 카메라 관절·어깨 추적은 인식에 계속 사용합니다.

YOLO 학습실의 '저장된 사진'에서 사진별 체크박스로 여러 장을 선택하거나 '현재 목록 전체 선택' 후 '선택 사진 삭제'를 누를 수 있습니다. 이름 필터가 '전체'이면 전체 사진, 특정 이름이면 해당 이름의 사진만 선택합니다. 필터를 바꾸면 선택은 해제되며 삭제 전에 개수를 확인합니다. 완료된 학습 모델과 기록은 유지됩니다. 일괄 삭제한 원본과 라벨링은 복구용으로 data/yolo-studio/deleted에 보관하므로 디스크 공간을 즉시 비우는 기능은 아닙니다.

탐지용 YOLO 모델을 연결하면 자동 지문자를 꺼 두거나 관절 추적·대기 자세 때문에 입력이 보류되어도 탐지 박스는 표시됩니다. '관절·손 박스 표시'를 켜고 교차 확인 방식을 선택하세요. 관절 단독 모드·녹화 중에는 YOLO 박스를 표시하지 않습니다. 표시 유효시간은 추론 완료 후 750ms이며, 1.5초 넘게 걸린 결과는 버립니다. 문장 입력의 관절 교차 확인·손 안정·최신 결과 조건은 그대로 적용합니다. 사진 분류용 모델에는 위치 박스가 없습니다.

수어 인식 화면과 YOLO 학습실에서 카메라를 켜면 고정 어깨 가이드가 표시됩니다. 양쪽 어깨를 원에 맞춰 촬영 위치와 거리를 맞추세요. 머리·목 가이드는 표시하지 않습니다. 화면 왼쪽 위의 '고정 어깨 가이드'로 끌 수 있습니다. 가이드는 사람을 따라 움직이지 않으며 촬영 사진·원본 영상·모델 입력에는 포함되지 않습니다. 카메라 각도와 화각은 동일하게 유지해야 반복 촬영 위치를 더 잘 맞출 수 있습니다.

프로젝트 파일은 frontend(화면), backend(서버), training(학습), tools(평가·백업), scripts(실행), docs(문서)로 분리했습니다. 실행은 최상위 run_tcn.bat를 사용하며 학습 자료는 기존 data 폴더에 그대로 있습니다. 전체 구조와 새 실행 경로는 ../README.md를 참고하세요.

다른 Windows 컴퓨터로 이전하는 방법은 [PORTABLE-SETUP.md](PORTABLE-SETUP.md)를 참고하세요. `scripts/setup.ps1`로 앱 자체 가상환경을 만들고 `run_tcn.bat`으로 5194 포트를 실행합니다. 기존 컴퓨터의 형제 프로젝트 환경은 호환용으로만 사용합니다.

## Gemini 문장 다듬기

- 연결된 서버에서는 API 키를 비워 두고 모델명만 수정해 `API 키 연결`을 누르면 현재 키를 유지하고 모델만 변경합니다. 재시작 후에는 키를 다시 연결해야 합니다.
- Flash 3 모델은 thinkingLevel=minimal, Flash 2.5 모델은 thinkingBudget=0으로 요청합니다. 보정에 불필요한 추론을 줄이기 위한 설정이며 외부 API의 가용성이나 속도를 보장하지 않습니다.
- 로컬 진단용 POST `/api/gemini/diagnose`는 `{"consent":true}` 요청에 한해 고정 예시 문장을 현재 모델과 진단 후보 모델에 각각 한 번 전송합니다. 모델별 10초 제한, 요청 간격을 적용하며 결과·소요시간·오류만 반환합니다. 모델과 키를 자동 변경하거나 저장하지 않습니다. 실제 Google API 사용량이 발생합니다.

- 오류는 HTTP 상태와 모델명, 20초 응답 시간 초과, DNS 조회, TLS 보안 연결, 일반 네트워크 실패, JSON 형식 오류를 구분해 표시합니다. HTTP 숫자는 Google 요청에서 받은 상태이며 로컬 서버 응답의 503과는 다릅니다. 오류 안내에는 API 키나 외부 서버 오류 본문을 노출하지 않습니다.

- Google에서 명시적으로 HTTP 500·502·503·504를 반환한 경우 브라우저가 3.2초 후 한 번만 재시도합니다. 시간 초과, 인증 실패, 사용량 제한, 로컬 요청 충돌은 자동 재시도하지 않습니다. 재시도도 Google API 요청이며 사용량이 발생합니다.
- 인식 원문과 한글 자모 조합은 입력 즉시 로컬에서 표시합니다. 입력이 0.7초 멈추면 최신 문장을 Gemini에 자동 전송합니다. 별도 문장 확정 버튼은 표시하지 않습니다.
- `Gemini API 설정`에서 키와 모델을 연결하고 `Gemini 자동 보정` 전송 동의에 체크합니다. 동의와 API 연결이 모두 준비되고 원문이 있을 때 자동 보정합니다.
- 입력이 멈추면 버튼 조작 없이 현재 문장을 Google로 전송합니다. 완료된 최신 응답만 표시합니다. 영상·관절 자료는 보내지 않습니다. Google API 요금과 사용량 한도가 적용됩니다.
- 한 번에 한 요청만 처리하고, 같은 입력의 중복 관찰은 무시합니다. 이전 요청 처리 중 입력이 바뀌면 최신 문장 하나만 대기시킵니다. 요청 간 최소 3.2초 간격은 유지합니다.
- 입력이나 말투가 바뀌면 이전 결과를 무효화하고 최신 문장을 자동 보정 대기에 넣습니다. 지우기와 동의 해제도 결과 반영·대기 요청을 취소합니다. 오류 시 원문과 로컬 문장을 보존합니다.
- Enter는 현재 표시된 문장을 읽고 음성 시작 시 비웁니다. Gemini 완료 전 Enter를 누르면 현재 로컬 문장을 읽습니다. AI 보정 결과를 읽으려면 보정 완료 후 Enter를 누르세요.
- 키는 서버 메모리에만 보관하며 재시작 시 다시 연결합니다. 환경변수 GEMINI_API_KEY, GEMINI_MODEL도 지원합니다. 기본 모델은 gemini-3.6-flash입니다. 키를 채팅·소스에 넣지 마세요.
- 자모는 요청 전과 응답 후 Hangul 라이브러리로 조합합니다. 이름·누락 글자를 추측하지 않도록 요청하지만 결과는 원문과 대조해야 합니다. 외부 API 응답 지연은 남을 수 있습니다. 여러 탭에서의 동시 요청은 서버 처리 제한이 적용됩니다.

## YOLO26 전환

- 학습실은 YOLO26n 손 박스 탐지와 YOLO26n-cls 사진 분류를 새로 학습합니다. 기존 사진, 박스, YOLO11 학습 기록은 보존됩니다.
- YOLO26 학습 라이브러리(8.4.189)는 `data/yolo26-runtime`에 별도로 설치되어 있습니다. 기존 YOLO11 환경은 유지합니다.
- 완료된 학습의 `fingerspell.onnx`와 해당 실행의 `labels.json`을 함께 연결하세요. 기존 YOLO11 파일을 연결하면 여전히 YOLO11로 동작합니다.
- YOLO26 탐지는 NMS-free `[1,N,6]` 출력과 `yolo26-end2end` 메타데이터를 사용합니다. 기존 YOLO11 원시 출력도 계속 지원합니다.
- 모델 교체가 실제 지문자 정확도 향상을 보장하지는 않습니다. 같은 검증 자료의 mAP와 실제 카메라 오입력을 따로 확인해야 합니다.

- YOLO 교차 확인의 관절 점수 기준은 30점입니다. 자동·수동 입력의 YOLO 기준은 60%이며 두 결과의 글자가 같아야 합니다. 관절 단독 방식은 기존 80점을 유지합니다. 점수는 정확도가 아니며, 기준 완화로 오인식이 늘 수 있습니다. 관절 후보 간 혼동·샘플 부족·추적 누락 등의 보류 조건은 유지됩니다.

- `YOLO + 관절 교차 확인`은 ONNX 모델 연결과 같은 자음·모음의 관절 샘플이 모두 필요합니다. YOLO 학습용 사진만 저장한 것은 DTW 관절 샘플 등록과 다릅니다.
- 페이지를 새로 열면 YOLO 모델 파일과 라벨 파일을 다시 연결해야 합니다.
- 자동 지문자 상태에 모델 미연결, 지문자 관절 샘플 없음, 저장 연결 실패를 표시합니다. 부족한 조건을 준비해도 두 결과의 일치·점수·손 안정·움직임 확인 조건을 통과해야 원문에 입력됩니다.
